# Apache Iceberg — Hands-On Learning POC

A learn-by-doing intro to Apache Iceberg tables, built for a Data Engineer moving into
ML/MLOps. You'll run a **real Iceberg table locally in minutes**, understand *why* it
works, then reproduce it in your **AWS account** with S3 + Glue + Athena.

## Suggested order (slow & foundational — understand each before moving on)

### 1. Run the local demo first (5 minutes, no AWS needed)
```bash
cd iceberg-poc
python local_demo.py
```
This creates a real Iceberg table, inserts retail sales, queries it, appends more data,
**time-travels** to an earlier version, **evolves the schema**, and prints the on-disk
file layout. Read the code top-to-bottom — it's heavily commented and each step maps 1:1
to an AWS step.

> Uses PyIceberg with a local SQLite catalog + a `file://` warehouse. Same API you'd use
> against AWS; only the catalog config differs.

### 2. Read the concepts — `01_concepts.md`
The *why*: the problem Iceberg solves, its three-layer file structure (metadata /
manifest / data), snapshots & time travel, the catalog, and how it compares to Delta/Hudi
and plain Parquet. ~10 minutes. This makes the AWS steps feel obvious.

### 3. Do it in AWS — `02_aws_guide.md`
Step-by-step console + SQL instructions to build the *same* `retail.sales` table with
**S3 + Glue Data Catalog + Athena** (fully serverless, costs pennies). Covers create,
insert, time travel, schema evolution, row-level UPDATE/DELETE, and **cleanup**.

## The one idea to remember

Iceberg turns "a pile of Parquet files in object storage" into a **real table** with
ACID transactions, schema evolution, and time travel — while your data stays as open
files you own. The only thing that changes between local and AWS is **the catalog**
(SQLite locally → AWS Glue) and **the warehouse** (`file://` locally → `s3://`).
Everything else is identical.
